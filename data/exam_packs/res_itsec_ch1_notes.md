# Introduction to Information Security & Security Architecture
**Course Code:** IT-SEC-401 (ITec4133) | **Learning Outcome:** `OUTCOME-ITSEC-CH1`

## Chapter Learning Focus & Cheat Sheet Notes

<a id="NOTE-CH1-001"></a>
### NOTE-CH1-001 (Question 1)
Integrity: Preserving data correctness and guarding against unauthorized modification or destruction.

<a id="NOTE-CH1-002"></a>
### NOTE-CH1-002 (Question 2)
Passive Attacks: Interception/snooping that compromises confidentiality without altering data or system states.

<a id="NOTE-CH1-003"></a>
### NOTE-CH1-003 (Question 3)
Traffic Analysis: Inferring intelligence by examining connection timing, volume, and message headers.

<a id="NOTE-CH1-004"></a>
### NOTE-CH1-004 (Question 4)
Replay Attack: Passive capture followed by active retransmission of legitimate data blocks.

<a id="NOTE-CH1-005"></a>
### NOTE-CH1-005 (Question 5)
Nonrepudiation: Mathematical or cryptographic proof of message origin/delivery that cannot be denied.

<a id="NOTE-CH1-006"></a>
### NOTE-CH1-006 (Question 6)
Threat vs. Attack: Threat is potential harm; attack is the realization/exploitation of a threat.

<a id="NOTE-CH1-007"></a>
### NOTE-CH1-007 (Question 7)
Economy of Mechanism: Keep security mechanisms simple to minimize bugs and vulnerabilities.

<a id="NOTE-CH1-008"></a>
### NOTE-CH1-008 (Question 8)
Security Mechanisms: Algorithms and tools (encipherment, signatures) implementing security services.

<a id="NOTE-CH1-009"></a>
### NOTE-CH1-009 (Question 9)
RBAC: Access rights tied to organizational functions and user roles.

<a id="NOTE-CH1-010"></a>
### NOTE-CH1-010 (Question 10)
Defense in Depth: Layered security mechanisms providing redundant asset protection.

<a id="NOTE-CH1-011"></a>
### NOTE-CH1-011 (Question 11)
Authentication: Verification of identity and message origin authenticity.

<a id="NOTE-CH1-012"></a>
### NOTE-CH1-012 (Question 12)
Availability Loss: Resource exhaustion resulting in service denial to authorized users.

<a id="NOTE-CH1-013"></a>
### NOTE-CH1-013 (Question 13)
MAC Control: Centralized access enforcement based on system-wide security clearances.

<a id="NOTE-CH1-014"></a>
### NOTE-CH1-014 (Question 14)
Data Integrity: Cryptographic checks detecting transit data alteration.

<a id="NOTE-CH1-015"></a>
### NOTE-CH1-015 (Question 15)
Fail-safe Defaults: Explicit permission requirement (default deny state).

<a id="NOTE-CH1-016"></a>
### NOTE-CH1-016 (Question 16)
ACL vs. Capability: ACLs store rights by column (with object); Capability lists store rights by row (with subject).

<a id="NOTE-CH1-017"></a>
### NOTE-CH1-017 (Question 17)
Trusted Third Party: Key distribution and trust management authority.

<a id="NOTE-CH1-018"></a>
### NOTE-CH1-018 (Question 18)
Active Data Modification: Unauthorized tampering of payload data during transit.

<a id="NOTE-CH1-019"></a>
### NOTE-CH1-019 (Question 19)
Audit Trail: Logging system transactions to maintain accountability and trace breaches.

<a id="NOTE-CH1-020"></a>
### NOTE-CH1-020 (Question 20)
Accountability: Traceability of all system events to responsible entities.
